# Профиль защиты FlyCam AeroScope/AgroScope

Статус документа: базовый инженерный профиль для подготовки к испытаниям.
Он не является сертификатом соответствия и не подтверждает применение
сертифицированного в Республике Казахстан средства криптографической защиты.

## Границы системы

В профиль входят Windows-клиент FlyCam, локальный/сетевой диспетчер, модуль
видеоаналитики, SQLite-журналы и их сетевые соединения. PX4, радиомодем,
камера, бортовой компьютер, операционная система, VPN/межсетевой экран и
инфраструктура ключей являются внешними компонентами и должны быть включены в
модель угроз конкретного объекта.

Диспетчер не имеет API для управления полётом или открытия грузового отсека.
Сетевой компромисс сервера поэтому не должен превращаться в прямой канал
исполнительных команд.

## Реализованный базовый профиль

| Контроль | Реализация | Ограничение |
|---|---|---|
| Шифрование канала | TLS, минимум 1.2, проверка серверного сертификата | Сам по себе OpenSSL/TLS не является заявлением о национальной сертификации |
| Шифрование данных на диске | Версионированные конверты AES-256-GCM для телеметрии, событий, обнаружений и текстовых полей заданий; контроль целостности и идентификатор ключа | Индексные метаданные SQLite остаются открытыми; провайдер является инженерным, а не сертифицированным СКЗИ |
| Ротация ключей данных | Набор ключей чтения и отдельный активный ключ записи; строгий режим запрещает запуск без ключа | Выдача, резервирование, уничтожение и аппаратное хранение определяются регламентом эксплуатанта |
| Взаимная аутентификация | Опциональный mTLS с заданным центром сертификации | Для QGC рекомендуется HTTPS через доверенный Windows CA; mTLS доступен серверным клиентам |
| Разделение прав | Ключи `viewer`, `ingest`, `operator`, `admin` | Ротация и выдача ключей остаются процедурой эксплуатирующей организации |
| Защита сравнения ключей | Сравнение через `hmac.compare_digest` | Не заменяет аппаратное хранилище ключей |
| Безопасный сетевой запуск | Сервер отказывается слушать внешние интерфейсы без ключа или обязательного mTLS | Обход разрешён только явным тестовым флагом |
| Аудит | Отказы аутентификации/авторизации и изменения заданий пишутся в SQLite без секретов | Нужны экспорт в SIEM, резервирование и политика неизменяемого хранения |
| Минимизация видео | Передаются метаданные распознавания, а не кадры | Политика обработки персональных данных определяется владельцем системы |
| Прослеживаемость модели | Имя и SHA-256 ONNX-модели в событии | Хэш доказывает идентичность, но не качество модели |

## Рекомендуемая конфигурация TLS

Односторонний TLS с отдельными ключами ролей:

```powershell
$env:FLYCAM_TLS_CERT = "C:\FlyCam\pki\server.pem"
$env:FLYCAM_TLS_KEY = "C:\FlyCam\pki\server.key"
$env:FLYCAM_ADMIN_KEY = "<отдельный ключ администратора>"
$env:FLYCAM_INGEST_KEY = "<отдельный длинный случайный ключ>"
$env:FLYCAM_VIEWER_KEY = "<другой длинный случайный ключ>"
$env:FLYCAM_OPERATOR_KEY = "<третий длинный случайный ключ>"
FlyCam-Dispatcher-Server.exe --host 0.0.0.0 --port 8443
```

Для mTLS дополнительно задаются `FLYCAM_TLS_CA` и
`FLYCAM_REQUIRE_CLIENT_CERT=1`. Закрытые ключи не должны находиться в
репозитории, журнале, параметрах GitHub Actions или резервной копии без
шифрования.

Для защиты SQLite задаются `FLYCAM_DATA_KEYS`, `FLYCAM_ACTIVE_DATA_KEY` и
`FLYCAM_REQUIRE_DATA_ENCRYPTION=1`. Ключи имеют длину 256 бит и передаются
только через защищённое секрет-хранилище процесса. В БД сохраняется лишь
несекретный идентификатор ключа. При ротации старый ключ сохраняется только на
период чтения/миграции существующих записей.

## Что требуется для формальной сертификации в Казахстане

1. Заказчик и профильный специалист определяют категорию информации, объект
   оценки, применимые нормы и точную редакцию стандартов.
2. Аккредитованная испытательная организация согласует программу: анализ
   исходного кода, испытания функций ИБ, нагрузочные испытания, обследование
   процессов разработки и, при необходимости, анализ недекларированных
   возможностей.
3. Выбирается сертифицированное/разрешённое криптографическое средство или
   сертифицированный TLS/VPN-шлюз. FlyCam подключается к нему через точку
   криптографической адаптации; выбор алгоритма нельзя делать только по
   названию ГОСТ или СТ РК.
4. Фиксируются версии ОС, PX4, QGC, библиотек, ONNX-модели, камеры, модема и
   схемы сети; создаются SBOM, управляемая сборка и подписанный дистрибутив.
5. Выполняются испытания по `VERIFICATION_PLAN_RU.md`, устраняются замечания,
   затем лаборатория оформляет протокол, а уполномоченный орган — итоговый
   документ в пределах выбранной схемы оценки.

Актуальные требования и область аккредитации необходимо проверять перед
подачей через официальные ресурсы:

- Государственная техническая служба и портал испытаний: <https://sts.kz/> и <https://synaq.sts.kz/>;
- национальный орган по стандартизации: <https://ksm.kz/>;
- Национальный удостоверяющий центр и SSL-сертификаты: <https://pki.gov.kz/>.

## Открытые риски до сертификационной фиксации

- нет выбранного сертифицированного криптопровайдера или VPN-шлюза;
- нет утверждённой модели угроз и классификации обрабатываемых данных;
- нет аппаратного управления жизненным циклом ключей;
- нет независимого пентеста, фаззинга API и анализа зависимостей;
- нет подписанного эталонного установщика и регламента обновлений;
- точность видеоаналитики не измерена на целевых сценах;
- стендовые и лётные испытания зависят от фактической камеры, радиоканала,
  Cube Orange, GPS и механизма грузового отсека.
