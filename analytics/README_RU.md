# FlyCam Video Analytics

Независимый от камеры модуль распознавания объектов для FlyCam
AeroScope/AgroScope Drone Control Center. Он читает RTSP/HTTP-поток, USB-камеру
или видеофайл, выполняет локальный ONNX-инференс и передаёт диспетчеру только
метаданные обнаружений. Кадры и видеопоток на диспетчерский сервер не
отправляются и по умолчанию не сохраняются.

Поддерживаемые классы по умолчанию: человек, автомобиль, автобус, грузовик,
мотоцикл и велосипед. Каждое событие содержит ID БПЛА, класс, уверенность,
нормализованную рамку, время, безопасное имя источника, разрешение кадра и
SHA-256 используемой модели. Сервер дополняет событие последней известной
позицией БПЛА.

## Быстрый запуск

Нужны Python 3.11+, зависимости из `requirements.txt` и разрешённая к
использованию ONNX-модель COCO. Поддерживается стандартный выход Ultralytics
без встроенного NMS: 84 столбца (YOLOv8/YOLO11) или 85 столбцов (YOLOv5).
Файл модели в репозиторий и установщик не входит: лицензию, набор данных,
точность и допустимость модели необходимо зафиксировать для конкретного
проекта.

```powershell
py -3 -m pip install -r analytics\requirements.txt
py -3 analytics\video_analytics.py `
  --source "rtsp://camera.local/live" `
  --model "C:\FlyCam\models\people-cars.onnx" `
  --vehicle-id 1 `
  --dispatcher-url "https://dispatcher.flycam.local:8443" `
  --api-key "INGEST_KEY"
```

Для USB-камеры укажите `--source 0`, для файла — полный путь. FlyCam удаляет
учётные данные RTSP из собственных журналов и событий, но их не следует вводить
в общедоступной командной строке: используйте `FLYCAM_VIDEO_SOURCE` или
защищённый файл запуска и отдельно проверьте диагностические журналы OpenCV/ОС.
Для нескольких БПЛА запускается отдельный экземпляр на каждый поток с его
`--vehicle-id`; диспетчер объединяет события в общей ленте без смешивания ID.

В Windows-установщик входит `FlyCam-Video-Analytics.exe`:

```powershell
FlyCam-Video-Analytics.exe --self-test
FlyCam-Video-Analytics.exe --source 0 --model C:\FlyCam\models\people-cars.onnx --vehicle-id 1
```

## Защищённое подключение

HTTPS проверяется через системное хранилище доверенных сертификатов. Для
внутреннего центра сертификации можно передать `--ca-cert ca.pem`. Клиентский
сертификат задаётся через `--client-cert client.pem --client-key client.key`.
Отключения проверки сертификата намеренно нет.

Для минимальных прав используйте `FLYCAM_INGEST_KEY` на сервере и передайте тот
же ключ модулю. Он разрешает только загрузку телеметрии, событий и обнаружений,
но не чтение данных и не изменение заданий.

## Производительность и приёмка

- `--frame-interval 3` анализирует каждый третий кадр;
- `--publish-interval 1.0` ограничивает частоту публикации;
- live-источник автоматически переподключается; `--max-reconnects 0` означает без ограничения;
- `--confidence 0.5` и `--nms 0.45` задают пороги;
- `--device cuda` включает OpenCV CUDA только в совместимой отдельной сборке;
- `--dry-run --once` проверяет поток и модель без отправки данных.

Перед эксплуатацией требуется репрезентативный набор дневных, ночных и
погодных сцен, измерение precision/recall по каждому классу, проверка ложных
тревог и задержки на целевом компьютере. Наличие движка не означает, что
конкретная модель прошла такую приёмку.
