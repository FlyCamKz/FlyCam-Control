# Готовность FlyCam AeroScope/AgroScope Drone Control Center

## Реализовано в исходниках

- фирменное название и логотип FlyCam;
- профиль Windows x64 для PX4 и Cube Orange;
- штатные карта, миссии, телеметрия, USB/COM и RFD900/SiK QGroundControl;
- отдельный модуль распознавания людей/транспорта для RTSP/HTTP/USB/файла;
- передача только метаданных распознавания, очистка секретов URL и SHA-256 модели;
- встроенный видеомодуль QGC отключён до выбора серийной камеры;
- панель грузового отсека Futaba S3001;
- команда `MAV_CMD_DO_SET_ACTUATOR` с выбором Set 1–6;
- подтверждение открытия и блокировка ручного открытия при armed/in-flight;
- различение подтверждённой команды и физического положения без датчика;
- локальный JSONL-журнал всех команд и отказов;
- передача телеметрии и событий на диспетчерский сервер;
- сервер SQLite, задания, статусы, обнаружения, журнал и веб-панель;
- TLS 1.2+, опциональный mTLS, раздельные ключи viewer/ingest/operator/admin;
- журнал отказов доступа и изменений заданий без сохранения секретов;
- запрет внешнего запуска сервера без ключа или обязательного mTLS;
- Docker Compose и запуск сервера в Windows PowerShell;
- GitHub Actions и локальный PowerShell-сценарий сборки Windows-установщика.

## Обязательные проверки перед полётом

- [ ] Уточнить установленную версию PX4 и обновлять её только по отдельной процедуре.
- [ ] Подключить S3001 через отдельный BEC 5–6 В, 2–3 А и общую землю.
- [ ] Снять пропеллеры и проверить направление/ход S3001 на стенде.
- [ ] Настроить AUX1 как `Peripheral via Actuator Set 1`.
- [ ] Подобрать PWM min/max, disarmed и failsafe без механического упора.
- [ ] Проверить USB и RFD900/SiK по отдельности, затем сценарий потери связи.
- [ ] Выбрать серийную камеру/кодек/протокол и проверить её поток не менее 30 минут.
- [ ] Зафиксировать разрешённую ONNX-модель и её SHA-256; измерить precision/recall на целевых сценах.
- [ ] Развернуть HTTPS с доверенным CA, раздельными ключами ролей и процедурой ротации.
- [ ] Согласовать модель угроз и сертифицированный криптопровайдер/VPN-шлюз с испытательной организацией.
- [ ] Выполнить независимый анализ исходного кода, пентест, нагрузочный тест и SBOM.
- [ ] Проверить RTL, геозону, батарейный failsafe и аварийную посадку в PX4 SITL.
- [ ] Проверить журналирование успешной, отклонённой и неподтверждённой команды.
- [ ] Собрать и подписать Windows-установщик на доверенной Windows-машине/CI.
- [ ] Провести наземные и лётные приёмочные испытания по утверждённой программе.

## Не следует считать готовым без оборудования

Физическое положение створки нельзя подтвердить программно, пока не установлен
концевик или магнитный датчик. Автоматическое открытие из миссии нельзя вводить
в эксплуатацию до проверки механизма и процедуры доставки. Публичное размещение
диспетчерского сервера требует HTTPS/VPN, межсетевого экрана, управления ключами
и мониторинга журнала. Добавленный TLS — техническая база, а не подтверждение
национальной криптографической сертификации. Модель распознавания и фактическая
камера также не считаются принятыми до измерения точности и задержки на целевом
оборудовании.
